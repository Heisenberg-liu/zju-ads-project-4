# Chapter 1 问题描述

## 1.1 实验目标

给定一个包含 n 个正整数的序列和阈值 m，统计其中 beautiful 子序列的数量。通过本实验，研究如何利用动态规划完成子序列计数，如何按元素值汇总状态，以及如何通过取模运算避免计数过大导致的溢出。

## 1.2 问题定义

若一个长度至少为 2 的序列中，存在一对相邻元素，其差的绝对值不超过 m，则该序列为 beautiful。

这里的相邻是选出的子序列中的相邻，而不是原序列中的相邻。例如，当原序列为 [1,100,2]、m=1 时，子序列 [1,2] 满足条件，但完整序列 [1,100,2] 不满足条件。

输入允许出现重复数字。本实验按照选取的下标区分子序列。例如 [1,1,1] 中有三个长度为 2 的子序列和一个长度为 3 的子序列，m=1 时答案为 4。

## 1.3 输入输出与约束

输入第一行为 n、m，第二行为 n 个正整数 a[i]。

- 2 ≤ n ≤ 100000。
- 1 ≤ m ≤ 1000。
- 1 ≤ a[i] ≤ 100000。

输出 beautiful 子序列数量对 P=1000000007 取模后的结果。单元素和空序列不计入答案。

## 1.4 问题难点

原序列有 2^n 个下标子集，逐一枚举不能用于大规模输入。直接枚举每个位置之前的所有位置，也会导致 O(n²) 的时间复杂度。另外，“至少有一对满足条件”不同于“所有相邻对都满足条件”：一个已经 beautiful 的子序列，即使接上距离很远的元素，仍然 beautiful。状态转移必须同时覆盖这两种形成方式。

# Chapter 2 算法设计与实现

## 2.1 状态定义

为便于与 C 程序一致，本章下标从 0 开始。

定义 DP[i] 为以位置 i 的元素结尾的 beautiful 子序列数量。它不包含“不选择 a[i]”的情况，也不包含单元素 [a[i]]。令 B 为此前所有 DP[j]（j<i）的总和，最终答案是全部 DP[i] 的总和。

以位置 j 结尾的所有非空子序列共有 2^j 个：位置 j 必选，而之前的 j 个位置分别可以选择或不选择。它包含单元素 [a[j]]，因此能够在接上合适的 a[i] 后形成长度为 2 的 beautiful 子序列。

## 2.2 状态转移

考察以 i 结尾的子序列中，倒数第二个被选中的位置 j。

若 |a[j]-a[i]|≤m，最后一对已经满足要求，因此任何以 j 结尾的子序列都可以接上 a[i]，贡献 2^j。

若 |a[j]-a[i]|>m，最后一对不能使序列变为 beautiful，因此前面的子序列必须已经 beautiful，贡献 DP[j]。

由此得到：

\[
DP[i]=\sum_{\substack{j<i\\|a[j]-a[i]|\le m}}2^j
+\sum_{\substack{j<i\\|a[j]-a[i]|>m}}DP[j].
\]

令 Anear 为此前附近值对应的 2^j 之和，Dnear 为此前附近值对应的 DP[j] 之和，则：

\[
\boxed{DP[i]=B-Dnear+Anear\pmod P.}
\]

B 已包含所有此前 beautiful 子序列的贡献。先减去附近的 beautiful 贡献，再加入附近的全部贡献，可以保证既不遗漏也不重复。DP[i] 无需额外加 1，最终答案也无需减 n。

例如序列 [1,2,100]、m=1：处理 1 时 DP=0；处理 2 时，[1] 接上 2 得到 [1,2]，DP=1；处理 100 时，[1,2] 虽然最后一对距离较远，但原来已经 beautiful，因此得到 [1,2,100]，DP=1。最终答案为 2。

## 2.3 值域桶

程序使用两个数组按数值保存累计贡献：

| 变量 | 含义 |
| --- | --- |
| bucket_allcase[v] | 此前所有 a[j]=v 的 2^j 之和 |
| bucket_DP[v] | 此前所有 a[j]=v 的 DP[j] 之和 |
| sum_DP_all | 此前全部 beautiful 子序列数量，即 B |
| power | 当前的 2^i mod P |

查询时只扫描 [a[i]-m,a[i]+m] 与有效值域的交集。桶中保存的是总和，因此即使同一数值出现多次，也不用逐个访问这些位置。

程序下界实际裁剪到 0；由于输入均为正整数，第 0 号桶始终为零，不影响结果。上界裁剪到 100000。

## 2.4 执行流程与关键实现

1. 清空两个桶，将 B 初始化为 0、power 初始化为 1。
2. 读取当前元素，扫描附近桶，得到 Anear 和 Dnear。
3. 根据 B-Dnear+Anear 计算当前 DP。
4. 将当前的 power 和 DP 分别累加到相应数值的两个桶中，更新 B。
5. 将 power 翻倍并取模，为下一个位置准备。
6. 处理完全部元素后输出 B。

当前代码在附近区间查询结束后、计算 DP 之前更新 bucket_allcase。由于 Anear 已经保存在局部变量中，此更新不会污染本轮查询，等价于上面的流程。

所有计数更新均取模。power 通过逐轮乘 2 得到，避免使用浮点 pow 计算大整数。DP 转移在取模前加 P，避免减法产生负余数；中间运算采用 long long。动态分配 DP 数组时使用 sizeof(long long)，与指针类型保持一致。

现有注释已说明 DP、两类附近贡献及总和的含义。为满足“充分注释”的要求，正式提交前还可补充 power、查询时序及取模的目的，重点解释算法原因，而非逐行翻译语句。

## 2.5 正确性证明

**初始情况。** 处理位置 0 时，桶与 B 均为零，故 DP[0]=0。单元素不能 beautiful，初始状态正确。

**归纳步骤。** 假设此前各 DP 值均正确。任意以 i 结尾的 beautiful 子序列都有唯一的倒数第二个位置 j。若最后一对满足阈值，则所有以 j 结尾的子序列均能扩展；否则只有此前已 beautiful 的子序列能扩展。这两个类别互斥且覆盖所有可能，不同 j 又对应不同下标选择，因此转移不重不漏。桶只在查询结束后加入当前贡献，保证计算时只考虑 j<i。于是 DP[i] 正确。

**最终结果。** 每个 beautiful 子序列都有唯一的最后位置，因此将全部 DP[i] 相加，恰好得到题目要求的答案。

## 2.6 复杂度

两个长度约为 V=100000 的桶需要 O(V) 初始化。每个元素最多检查 2m+1 个桶编号，每次访问两个桶，故总时间复杂度为 O(V+nm)。当 n=100000、m=1000 且当前值远离值域边界时，内层循环约执行 2.001 亿次。

实际程序还保存了长度为 n 的 record 和 DP 数组，因此空间复杂度为 **O(V+n)**，不是仅 O(V)。两个桶与两个动态数组的有效存储在最大规模时合计约 3.2 MB（不含运行时其他开销）。

若不保留历史 record 和 DP，仅使用当前元素和当前 DP，可以将空间降至 O(V)；若用树状数组实现区间求和，可以将时间降至 O(V+n log V)。这些是可选优化，当前提交实现仍为逐桶扫描。

# Chapter 4 分析、纠错与讨论

## 4.1 正确性测试分析

固定用例覆盖了题意中容易混淆的边界和计数方式。尤其是 [1,2,100] 与 [1,100,2] 的对照，能够区分“存在一对相邻元素满足条件”和“任意两个元素接近”这两个不同判断。

重复值测试同时验证桶的累计方式与按下标计数。40 和 100 个相同元素使计数超过普通整数直接表示范围，针对此前漏取模的问题进行回归。全部通过说明当前版本在已测输入中正确处理了这些问题。

## 4.2 性能分析

m 固定为 1000 时，主要工作量随 n 线性增长。本次 n 从 10000 增加到 100000，耗时从约 0.10 秒增至约 0.89 秒，与 O(nm) 的分析一致。较小规模下进程启动开销所占比例较高，因此不能期望各规模耗时严格成比例。

全相同且值为 50000 的构造虽然数值分布简单，但当前程序仍逐桶扫描，不会跳过空桶，因而覆盖了最大附近区间宽度。在本机、上述编译配置下，最大规模用例正常结束且输出正确；由于尚未提供评测平台时限，不能保证所有平台均不会超时。

本轮尚未执行 n=100000 的全值域随机对拍，也未测量峰值内存。若需要更完整实验，可增加独立树状数组参考程序、重复计时和不同 m 的对照。

## 4.3 开发过程中的问题及修复

| 问题 | 原因 | 当前处理 |
| --- | --- | --- |
| 初始小数据全部错误 | 输入阶段提前把当前和未来位置贡献放入桶 | 改为从左到右查询后更新 |
| 桶中 DP 更新位置错误 | 用位置 i 代替数值 a[i] 作为桶编号 | 改为按 record[i] 更新 |
| 大数计数不准确 | 用浮点 pow，且计数未及时取模 | 用整数倍增维护 power，计数更新取模 |
| 小数据通过、较大重复数据失败 | bucket_allcase 的累加漏取模 | 补上该桶更新的取模 |
| 内存越界 | DP 改为 long long 后仍按 sizeof(int) 分配 | 按 sizeof(long long) 分配 |
| 输出类型不一致 | long long 表达式使用 %d 输出 | 当前使用 %lld |

这些问题表明，小数据通过并不能证明整数范围及内存使用正确。测试需要同时覆盖算法语义、重复值、数值增长和规模上限。

## 4.4 实现改进空间

当前程序仍包含未使用的 math.h，可删除；动态数组应在结束时释放，并可补充 scanf 返回值与内存申请结果的检查。两个桶当前位于函数局部栈上，合计约 1.6 MB，在栈限制较小的平台上可改为静态存储或堆分配。以上建议不改变状态转移。

为满足注释评分要求，应明确标注“查询必须只包含此前位置”和“power 对应零基下标下的 2^i”。如果性能测试或评测时限要求更高，再将区间扫描替换为树状数组查询。

## 5.2 实验总结

本实验使用“以当前位置结尾的 beautiful 子序列数”作为状态，按最后一对是否满足阈值分类，得到 B-Dnear+Anear 的转移。通过值域桶汇总相同数值的贡献，避免逐个枚举此前位置，将朴素 O(n²) 转移改为 O(nm+V)。

当前代码在本轮 215 组测试中全部通过，其中包括 n=100000、m=1000 的最大规模重复值测试。实验过程中通过小规模穷举、重复值回归和公式可验证的大数据测试，分别定位并验证了计数、取模和内存分配问题。后续工作是按课程章节模板整理成稿，并在指定评测环境中确认编译兼容性与时间限制。
